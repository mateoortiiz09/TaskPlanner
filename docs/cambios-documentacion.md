# Cambios para los documentos de requerimientos y diseño

Esta lista identifica diferencias que deben reflejarse en el Documento de
Requerimientos (Word) y el Documento de Diseño. Las rutas indican dónde consultar
la implementación actual.

| Tema | Qué decía el plan original | Qué quedó implementado | Dónde se ve en el código |
|---|---|---|---|
| Sensibilidad y permisos | Tres niveles de sensibilidad y permisos explícitos de acceso. | Dos niveles: normal y «Información restringida»; se quitaron permisos explícitos y los responsables siempre ven sus tareas. | `tareas/models.py`, `tareas/forms.py`, `autorizacion/reglas.py`, `tests/test_sensibilidad.py` |
| Administración de usuarios | La Subgerencia podía participar en la gestión de usuarios. | Solo el Administrador gestiona usuarios y áreas; la Subgerente no administra cuentas. | `cuentas/views.py`, `cuentas/urls.py`, `tests/test_administracion_usuarios.py`, `tests/test_matriz_permisos.py` |
| Facultades del Administrador | Se restringía la creación y edición de tareas del Administrador en general. | Puede crear y editar tareas no restringidas; consulta las restringidas enmascaradas y puede eliminarlas o recuperarlas. No puede crear ni editar restringidas, cambiar estados, completar ni adjuntar. | `autorizacion/reglas.py`, `tareas/views.py`, `tareas/servicios.py`, `tests/test_matriz_permisos.py` |
| Base de datos | PostgreSQL 17 figuraba en el material anterior. | El objetivo vigente es PostgreSQL 18. | `config/settings/base.py`, `README.md` |
| Configuración de base de datos | `DATABASE_URL` con django-environ. | Variables `POSTGRES_*` cargadas desde `.env` con python-dotenv. | `.env.example`, `config/settings/base.py` |
| README | README ubicado en `.vscode/` y contenido parcialmente desactualizado. | README vigente en la raíz del repositorio. | `README.md` |
| Bloqueo de inicio de sesión | No quedaba especificado el alcance del bloqueo. | django-axes limita fallos por cuenta e IP. | `config/settings/base.py`, `cuentas/axes.py`, `tests/test_autenticacion.py` |
| Panel de administración | Panel estándar sin tema ni navegación de regreso definidos. | `/gestion-interna/` usa django-unfold y contiene un enlace de regreso a TaskPlanner. | `config/urls.py`, `config/settings/base.py`, `tests/test_admin_tema.py`, `tests/test_admin_regreso.py` |
| Tareas completadas | No se prohibía editar o cambiar el estado tras completar. | No se editan ni cambian de estado; no se permite reapertura. | `tareas/servicios.py`, `autorizacion/reglas.py`, `tests/test_tareas_flujo.py` |
| Traducciones | La compilación podía depender de herramientas externas y los binarios no estaban claramente incluidos. | `scripts/compilar_traducciones.py` genera los `.mo`, que se guardan en Git junto con los `.po`. | `scripts/compilar_traducciones.py`, `locale/es/LC_MESSAGES/django.po`, `locale/es/LC_MESSAGES/django.mo`, `locale/es_CO/LC_MESSAGES/django.po`, `locale/es_CO/LC_MESSAGES/django.mo` |
| Correo de producción | Se consideraba SMTP cifrado como alternativa de producción. | Microsoft Graph con credenciales de aplicación; el permiso de Exchange se limitará al buzón de notificaciones mediante RBAC. | `notificaciones/graph.py`, `notificaciones/servicios.py`, `tests/test_graph.py` |
| Tipos y tamaño de adjuntos | El listado y la validación final no estaban alineados. | PDF, DOCX, XLSX, PNG y JPG/JPEG; máximo configurable de 20 MB y validación por firma; se rechazan macros y SVG. | `adjuntos/validacion.py`, `config/settings/base.py`, `tests/test_adjuntos.py` |
| Cifrado de adjuntos | El cifrado se asociaba solo al nivel de sensibilidad anterior. | AES-256-GCM para adjuntos de tareas restringidas; se cifran también los existentes cuando la tarea pasa a restringida. | `adjuntos/cifrado.py`, `adjuntos/servicios.py`, `tareas/servicios.py`, `tests/test_adjuntos.py` |
| Almacenamiento de adjuntos | No se detallaba el aislamiento del almacenamiento del sitio web. | Los archivos se guardan en un directorio de almacenamiento configurable fuera del proyecto web. | `config/settings/base.py`, `adjuntos/almacen.py`, `tests/test_adjuntos.py` |
| Auditoría | El esquema de eventos no estaba actualizado con el código. | Registro de solo inserción; no conserva nombres de tareas, nombres de archivos ni contraseñas. | `auditoria/models.py`, `auditoria/servicios.py`, `tests/test_auditoria.py` |
| Notificaciones | Envío inmediato sin bandeja de salida unificada. | Bandeja persistente con clave única, reintentos y cancelación de avisos que ya no aplican. | `notificaciones/models.py`, `notificaciones/servicios.py`, `tests/test_notificaciones.py` |
| Tareas y calendario de recordatorios | La planificación periódica no especificaba la implementación efectiva. | Recordatorios de día anterior, vencimiento, primer día de atraso y semanal; se generan cada hora desde las 7:00. | `notificaciones/recordatorios.py`, `notificaciones/management/commands/generar_recordatorios.py`, `tests/test_recordatorios.py` |
| Cola de trabajo | Se contemplaba una infraestructura separada de tareas programadas. | Django-Q2 usa PostgreSQL como cola; `programar_tareas` registra el envío cada minuto y los recordatorios cada hora. | `config/settings/base.py`, `notificaciones/management/commands/programar_tareas.py` |
| Comandos de desarrollo | No se identificaban claramente los comandos locales y sus límites. | `crear_datos_demo` y `cargar_datos_demo` requieren `DEBUG=True`; las operaciones de correo y recordatorios tienen comandos propios. | `cuentas/management/commands/crear_datos_demo.py`, `tareas/management/commands/cargar_datos_demo.py`, `notificaciones/management/commands/` |
| Servidor de producción | Debian 13, Gunicorn, Caddy, systemd, ClamAV, LUKS, restic y GlitchTip. | Windows: Waitress en lugar de Gunicorn; Caddy sin cambios; WinSW o NSSM en lugar de systemd; Microsoft Defender en lugar de ClamAV; BitLocker en lugar de LUKS; restic con el Programador de tareas; registros en archivo y Visor de eventos en lugar de GlitchTip. | Decisión registrada en `docs/decisiones.md`; documentación de despliegue pendiente en `docs/despliegue-windows.md` |
